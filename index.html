INCIDENT FORENSICS #MJ-084

Sensor Read Timeout (NaN Readings)

Resolution Verified
Recorded Symptom:

ESP32 boots normally, but Serial Monitor displays continuous "Failed to read from DHT sensor! Returning NaN".

Physical / Electrical Root Cause:

The DHT22 data line requires an open-drain pull-up. The student omitted the 10kΩ resistor, causing the data pin to float. Consequently, the start transmission pulse sent by the ESP32 was never acknowledged by the sensor.

Prescribed Resolution & Fix:

1. Insert a 10kΩ resistor across DHT22 Pin 1 (3.3V) and Pin 2 (Data).
2. Add a 2-second initial warm-up delay in setup() before calling dht.readTemperature().

Examiner Relevance: Will be sent to Viva Predictor Logged in Personal Progress

EXAMINER SIMULATION — TARGETING MISTAKE #MJ-084

"Why did your sensor return NaN before adding a pull-up resistor?"

Difficulty: 4/5
Comprehensive Model Answer:

"The DHT22 single-wire protocol utilizes an open-drain output transistor. An open-drain pin can actively pull the signal line to GND (Logic LOW), but cannot pull it HIGH on its own. Without an external 10kΩ pull-up resistor to the 3.3V rail, the line remains in a floating, high-impedance state. Consequently, the microcontroller cannot detect the 80µs initial LOW and 80µs HIGH handshake response from the sensor, leading to a timeout exception and returning NaN."

Examiner's Likely Follow-Up Trap:

"Could you have used the microcontroller's internal pull-up resistor instead of an external one? Why might an internal 50kΩ pull-up fail at longer wire lengths?"

Technical Architecture

System Workflow & Inter-Module Feedback

How the 7 modules seamlessly communicate with each other to turn raw student lab struggles into comprehensive mastery.

STAGE 1: INGESTION & SETUP

Multimodal Visual Pipeline

Module 1 parses project titles and checks workbench photos with computer vision. Detected components automatically populate Module 2 (Components Catalog) and generate sequenced instructions in Module 3 (Process).

STAGE 2: EXECUTION & FORENSICS

In-Lab Safety & Anomaly Engine

During execution in Module 3, any unexpected behavior or short circuit is routed directly into Module 4 (Mistake Journal). Root-cause analysis resolves the problem on the fly, preventing blown ICs.

STAGE 3: SYNTHESIS & DEFENSE

Feedback Loop to Viva & Progress

Module 5 logs actual observations and error percentages. Module 6 consumes both the experiment context and the specific errors logged in Module 4 to simulate tough viva questions. Module 7 indexes recurring mistakes across terms.
